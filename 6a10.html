Puntos 6–10

6) Estáticos vs Instancia (contador de operaciones)

Objetivo: Diferenciar miembros estáticos y de instancia.

Implementación: En CalculadoraBasica, agregar la propiedad estática public static int ConteoOperaciones { get; private set; } que incrementa en cada método público.

Concepto: Los miembros static pertenecen a la clase, no al objeto. Se usan para compartir datos o comportamientos globales entre instancias.

classDiagram class CalculadoraBasica { + static int ConteoOperaciones + double Sumar(a,b) + double Restar(a,b) + double Multiplicar(a,b) + double Dividir(a,b) } CalculadoraBasica : ConteoOperaciones++ en cada método

7) Herencia: Vehículo, Auto, Bicicleta

Objetivo: Reutilizar código con herencia simple.

Implementación: Vehiculo tiene Marca y Arrancar(). Auto hereda de Vehiculo y agrega Puertas. Bicicleta hereda de Vehiculo y agrega TieneCanastilla.

Concepto: La herencia permite extender una clase base agregando o especializando comportamientos.

classDiagram class Vehiculo { + string Marca + void Arrancar() } class Auto { + int Puertas } class Bicicleta { + bool TieneCanastilla } Vehiculo <|-- Auto Vehiculo <|-- Bicicleta

8) Polimorfismo con virtual/override

Objetivo: Aplicar polimorfismo entre clases derivadas.

Implementación: Vehiculo declara virtual string Describir(). Auto y Bicicleta lo sobreescriben (override) para incluir sus propios datos.

Concepto: El polimorfismo permite que un mismo método tenga comportamientos distintos según el tipo real del objeto.

classDiagram class Vehiculo { + string Marca + virtual string Describir() } class Auto { + int Puertas + override string Describir() } class Bicicleta { + bool TieneCanastilla + override string Describir() } Vehiculo <|-- Auto Vehiculo <|-- Bicicleta

9) Interfaz INotificable

Objetivo: Definir un contrato común entre implementaciones distintas.

Implementación: Crear interface INotificable { void Enviar(string mensaje); }. NotificadorEmail y NotificadorSms implementan Enviar(). Una función Avisar() recibe el canal y el cliente.

Concepto: Las interfaces definen comportamientos que varias clases pueden implementar, permitiendo el polimorfismo por interfaz.

classDiagram class INotificable { + void Enviar(string mensaje) } class NotificadorEmail { + void Enviar(string mensaje) } class NotificadorSms { + void Enviar(string mensaje) }

10) Clase abstracta: Figura

Objetivo: Usar clases abstractas para definir contratos y reutilizar código común.

Implementación: abstract class Figura con método abstracto Area() y método concreto MostrarArea(). Subclases: Circulo (radio) y Rectangulo (ancho, alto).

Concepto: Las clases abstractas establecen una estructura común y obligan a las derivadas a implementar ciertos métodos.

classDiagram class Figura { + abstract double Area() + void MostrarArea() } class Circulo { + double Radio + override double Area() } class Rectangulo { + double Ancho + double Alto + override double Area() } Figura <|-- Circulo Figura <|-- Rectangulo
