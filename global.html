Estructura Conceptual del Proyecto Taller POO

📘 Visión general

El proyecto TallerPOO está diseñado para reforzar los conceptos fundamentales de la programación orientada a objetos (POO) en C#.

Se organiza de forma modular, donde cada componente cumple un propósito específico:

  • Program.cs: punto de entrada del programa. Controla la ejecución general y llama a los ejercicios.
  • Ejercicios.cs: agrupa todos los métodos estáticos Ejercicio1() a Ejercicio15(), cada uno demostrando un concepto POO.
  • Modelos/: contiene las clases utilizadas en cada ejercicio, como Persona, CalculadoraBasica, Vehiculo, Figura, etc.
La estructura sigue un flujo claro: Program → Ejercicios → Clases del modelo.

⚙️ Flujo principal del programa

Cuando ejecutas el proyecto con dotnet run, se inicia el método Main() dentro de Program.cs. Desde ahí, el usuario puede escoger o se ejecutan secuencialmente los ejercicios definidos en la clase Ejercicios.

🏗️ Estructura de clases (modelo conceptual)

Las clases del proyecto se dividen por propósito pedagógico, pero mantienen una estructura coherente:

🧠 Interpretación conceptual

Podemos imaginar el flujo de ejecución como una conversación entre los componentes del proyecto:

Program: “Necesito ejecutar el Taller.” Ejercicios: “Perfecto, tengo quince ejemplos listos.” Program: “Ejecuta el 1.” Ejercicios: “Voy a usar la clase Persona para demostrarlo.” Persona: “Hola, soy Ana y tengo 20 años.”

Y así sucesivamente: Program orquesta, Ejercicios agrupa, y las clases modelo viven los conceptos de POO:

  • Encapsulamiento: clases con propiedades controladas.
  • Herencia: clases derivadas que comparten comportamientos.
  • Polimorfismo: métodos que se comportan diferente según el tipo.
  • Abstracción: clases base que definen contratos comunes.

📦 Conclusión

El proyecto TallerPOO está organizado de forma escalonada y didáctica:

  1. El programa principal (Program) controla el flujo.
  2. La clase Ejercicios actúa como un “índice” de prácticas.
  3. Las clases del modelo implementan los conceptos clave de POO.

Este diseño no solo demuestra los fundamentos de la POO, sino que también enseña buenas prácticas de modularidad, claridad y separación de responsabilidades.
